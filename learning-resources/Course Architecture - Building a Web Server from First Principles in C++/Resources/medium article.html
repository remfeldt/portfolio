Understanding web servers

A web server is a system responsible for delivering web pages to clients (typically web browsers) over the Internet or an intranet. Its primary function is to store, process, and deliver web content to users. Here are the key components and primary functions of a web server:

Primary Functions of a Web Server:

  1. Listening for Requests

The web server listens for incoming HTTP requests from clients (web browsers, mobile apps, etc.) on a specific port (usually port 80 for HTTP and port 443 for HTTPS).

2. Processing Requests

When a request is received, the web server processes it to determine what is being requested. This includes parsing the HTTP request to extract details such as the method (GET, POST, etc.), requested resource (URL), headers, and possibly a message body.

3. Mapping Requests to Resources

The server maps the requested URL to a specific resource on the server. This could be a static file (HTML, CSS, JavaScript, images, etc.) or a dynamic resource that requires additional processing (such as a PHP script, a Python application, or a Java servlet).

4. Generating Responses

For static resources, the server simply reads the file from the filesystem and sends its contents back to the client.

For dynamic resources, the server may execute a script or application to generate the response content. This often involves querying a database, performing business logic, and rendering a view.

5. Sending Responses

The server constructs an HTTP response, which includes a status line (indicating the status of the request, such as 200 OK or 404 Not Found), response headers (metadata about the response), and the response body (the actual content).

The response is then sent back to the client, which renders the content for the user.

6. Logging and Monitoring

Web servers typically keep logs of all requests and responses. These logs can be used for monitoring server performance, analyzing traffic, debugging issues, and improving security.

7. Handling Concurrency

A web server must efficiently handle multiple simultaneous requests. This can involve using threading, asynchronous I/O, or event-driven architectures to manage concurrency.

8. Security

Web servers implement various security measures to protect against threats such as DDoS attacks, SQL injection, cross-site scripting (XSS), and cross-site request forgery (CSRF). They also manage SSL/TLS certificates to ensure secure HTTPS communication.

Example Workflow

  1. Client Request: A user types www.example.com/index.html into their browser.
  2. DNS Resolution: The browser contacts a DNS server to translate www.example.com into an IP address.
  3. TCP Connection: The browser establishes a TCP connection to the web server at the resolved IP address on port 80 or 443.
  4. HTTP Request: The browser sends an HTTP GET request for /index.html to the web server.
  5. Request Handling: The web server receives the request, maps /index.html to the corresponding file on the server, reads the file, and generates an HTTP response.
  6. HTTP Response: The web server sends the response, including the contents of index.html, back to the browser.
  7. Rendering: The browser receives the response, parses the HTML, and renders the web page for the user to view.

How Socket and Server-Client Model Works

Socket Programming

A socket is an endpoint for communication between two machines. It is used to establish a connection, send data, and receive data over a network. Sockets can operate in different domains, such as:

  • AF_INET: use IPv4 (vs IPv6)
  • SOCK_STREAM: use TCP (vs UDP)
  • INADDR_ANY: the server accepts connections from any network interface

Server-Client Model

The server-client model is the basis of network communication, where one machine (the server) provides resources or services, and another machine (the client) accesses those resources or services. Here’s how it works:

  1. Server Setup:
  • Create a Socket: The server creates a socket using the socket() function.
  • Bind to an Address: The server binds the socket to a specific IP address and port using the bind() function. This address and port will be used by clients to connect to the server.
  • Listen for Connections: The server listens for incoming connections using the listen() function, putting the socket into a passive mode where it waits for connection requests from clients.
  • Accept Connections: When a client attempts to connect, the server accepts the connection using the accept() function, which creates a new socket dedicated to this particular client.

2. Client Setup:

  • Create a Socket: The client creates a socket using the socket() function.
  • Connect to the Server: The client connects to the server’s IP address and port using the connect() function.

3. Data Exchange:

  • Once connected, the client and server can exchange data. The client sends an HTTP request, and the server processes the request and sends back an HTTP response.
  • Send Data: The client and server send data using the send() function.
  • Receive Data: The client and server receive data using the recv() function.

4. Close Connection:

  • After the data exchange is complete, either the client or the server (or both) can close the connection using the close() function.

Framing HTTP Response

The server parses the HTTP request to understand the client’s needs, such as the requested file path and HTTP method. Once the request is parsed, the server locates and opens the corresponding file. After retrieving the file’s content, the server constructs an HTTP response, setting headers like “Content-Type” to specify the MIME/type of the content. Finally, the server sends this framed response back to the client or browser, ensuring the requested content is correctly formatted and ready for display or further processing.
